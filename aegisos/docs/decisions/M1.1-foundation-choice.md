## The Options

### Option A: Debian-based (e.g., Debian 12 minimal)

**Advantages**
- Mature, stable package ecosystem
- `debootstrap` gives a clean minimal base
- Well-documented security hardening guides (CIS benchmarks, Debian hardening)
- `.deb` format is well-understood; reproducible builds via `debrepro`
- AppArmor is default LSM — lower friction for M2.1

**Disadvantages**
- Slower release cycle (packages may be old)
- Larger base footprint than Yocto
- systemd default init — requires deliberate removal if you choose runit/s6

**Fit for AegisOS**
Debian is the lowest-risk base for a solo project. The ecosystem handles packaging
complexity so you can focus on the policy engine. Best choice if you want to ship
a working Phase 2 fastest.

---

### Option B: Arch-based (e.g., Arch Linux or Artix)

**Advantages**
- Rolling release — always current packages
- Minimal base by default (no unnecessary services)
- AUR gives flexibility
- Pacman is simpler than apt for custom packaging

**Disadvantages**
- Rolling release = potential instability at inopportune times
- Less mature reproducible build tooling
- Smaller enterprise security hardening documentation base
- AppArmor support is secondary (SELinux requires manual setup)

**Fit for AegisOS**
Good if you already know Arch deeply. Rolling release is a liability for a
security-focused OS — you don't want a surprise update to break your LSM policy.

---

### Option C: Yocto/Buildroot

**Advantages**
- Maximum control — you define exactly what's in the image
- Reproducible builds are the default, not an afterthought
- Cross-compilation support
- Production-grade embedded/security OS deployments use this path

**Disadvantages**
- Steep learning curve (Yocto alone is months of study)
- Long iteration cycles — a full rebuild takes 30–90 minutes
- Much harder to package third-party tools
- Overkill for Phase 0–2; the tooling is the OS, not the policy engine

**Fit for AegisOS**
Best end-state for a production AegisOS, but the wrong starting point for a
solo developer still mastering kernel modules. Revisit in Phase 4 if you need
hardware-specific images.
